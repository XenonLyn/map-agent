# 隐含约束提议的标注规程 v1

## 标注对象

意图层（`llmPlan`）从自然语言描述中推断出的、描述**没有明写**的地理约束。
每条提议包含：主体聚落、约束内容、以及模型给出的理由（rationale）。

本轮共 20 条（`proposals_round1.csv`），由 2026-09 的一次 `runExtraction()` 产生，
覆盖 4 个预设描述（coast / kingdom / island / impossible）。

## 标注流程

1. **两名标注者独立标注**，互相不讨论，分别填 `label_A` 和 `label_B` 列。
2. 标注时**只看描述原文和 rationale，不看生成出来的地图**——判断的是"这个推断是否合理"，
   而不是"它在这张图上是否碰巧成立"。描述原文见 `descriptions.md`。
3. 标注完计算一致性（`node ../tests/kappa.js annotation/proposals_round1.csv`）。
   kappa < 0.6 说明标签定义有歧义，需要先讨论修订规程，再重标。
4. 分歧条目逐条讨论，形成共识标签，填进 `note` 列说明理由。

## 三个标签

### 合理
地理上**确有必然性**：如果不满足这条约束，描述里的那个聚落就无法成立或无法运转。

- 例：山口关隘 → `易守难攻`。关隘存在的意义就是控扼通道，不占地势就不成其为关隘。
- 例：渔村 → `临海`。不临海就不是渔村。

### 牵强
**听起来像常识，但地理上不必然**。这类提议最危险：它会被验证器检查、检查失败会触发迁址，
于是一个可有可无的推断变成了真实的空间扭曲。

- 例：要塞 → `路程不超过 5 天 → 王都`。真实的边境要塞往往离首都很远，正因为它在边境。
- 判断要点：能否举出反例？如果"不满足这条也完全说得通"，就是牵强。

### 错误
推理依赖**生成之前未知的信息**，或者**谓词用错**。

- 例：A `位于其下游` B，但描述中从未说明两者在同一水系——拓扑在生成前是未知的。
- 例：把"繁华"推成 `易守难攻`（谓词错配）。

## 额外记录（可选，填在 note 列）

- 天数类提议：模型给出的天数是否有依据？（它在这一轮并不知道地图尺度）
- 是否存在同一理由重复套用到多个聚落的情况（凑数迹象）。

## 已知的方法学缺陷

- 本轮的提示词、示范推理和初版标签定义均由同一来源（与本项目的开发过程）产生，
  因此**必须由项目成员之外或至少开发者之外的人独立标注**，否则结论不可用。
- 标准答案（gold WorldSpec）来自手写预设，带有作者偏好，
  报告中应说明其来源，不应表述为客观基准。
- 4 个描述的样本量太小，且全部是前现代或近代小镇场景，
  结论不能外推到现代或科幻设定。
